# 踩坑记录（pitfalls）

> 每条：现象 → 根因 → 正确做法 → 验证日期。AI 编码前必读，避免重复踩坑。

## 1. python-pptx / power-pptx 的 fit_text() 对中文失效

- 现象：对中文文本调用 `fit_text()`，python-pptx 1.0.2 直接报 TypeError；power-pptx 2.13 不报错但只返回"放不下"，不给出正确断行。
- 根因：源码中断行逻辑用 `text.split()`，即按空格断词。中文没有空格，一整段被当成单个"超长单词"，无法在中间断开。
- 正确做法：中文一律走 `src/text_fit.py`（Pillow 逐字符测量 + 按字断行 + 二分字号 + 标点避头尾）。
- 验证日期：2026-10-18（本地实测）。

## 2. 行高不能用纯字形高度估算

- 现象：用 Pillow `getbbox` 测得的纯字形高度 × 行数，会低估实际行高，导致文字仍溢出。
- 正确做法：行高系数取字号的 1.2 倍（`line_factor=1.2`），实测与 LibreOffice 渲染吻合。
- 验证日期：2026-10-18。

## 3. 测量字体、渲染字体、PPT 字体名三处不一致则测量失效

- 现象：`text_fit.py` 用 A 字体测量，但系统/PPT 实际用 B 字体，算出的字号不匹配，仍可能溢出。
- 正确做法：测量用的字体文件、LibreOffice 可用的系统字体、PPT 中指定的字体名必须是同一套（见 fonts.md）。

## 4. 把丑 pptx 直接转图片，不会变美观

- 现象：期望"渲染成整页图片后达到命令行做不到的美观"，但直接 LibreOffice 转 pptx 得到的图，排版美观度没有提升。
- 根因：渲染只忠实呈现排版结果，python-pptx 对渐变、复杂版式、图文关系表达能力有限。
- 正确做法：v2 分阶段。M1 用 LibreOffice 渲染跑通闭环；M5 用 HTML/CSS 精排版 + Playwright 截图作为美观渲染源。
- 验证日期：2026-10-18（架构结论，非 bug）。

## 5. 无限缩字号不是解决内容超量的办法

- 现象：字号被压到很小仍硬塞，导致投影不可读。
- 正确做法：字号下限 10pt；`best_font_size` 返回 None 时，调用方必须精简文案或拆页，把问题反弹回内容阶段。

## 6. 外部平台链接抓取不可控

- 现象：小红书/抖音等平台有反爬、登录墙、服务条款限制。
- 正确做法：抓取先开 `spike/link-crawler` 验证；失败即降级为"用户上传截图"。不做绕过平台风控的尝试。

## 7. 微信公众号文章直接抓取被 robots 拦截

- 现象：常规抓取/浏览器打开微信公众号链接会遇到 robots 拦截或"环境异常"验证。
- 正确做法：仅作资料调研时，可尝试带微信内置浏览器 UA 的请求；自动化浏览器无法过验证。与本项目核心无关，仅记录。

## 8. 用户在 WPS 里手动改动后，必须与 manifest 比对

- 现象：无法知道用户改了哪一页、哪个元素。
- 正确做法：生成 v1 时同步输出 `manifest.json`（逐 shape 记录 id/文本/位置/尺寸/图片路径）；读回 v1 后做 diff。该能力正式开发前先做 `spike/pptx-diff`。

## 9. 插画不是独立元素就无法在 WPS 中拖动

- 现象：插画与背景合成一张图后，用户无法单独移动插画。
- 正确做法：插画必须输出为透明底独立 PNG，单独作为一个 picture shape 插入 v1。
