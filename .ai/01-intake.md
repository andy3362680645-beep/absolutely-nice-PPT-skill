# 01 · 需求访谈协议

> 阶段 1 执行规范。目标：把模糊想法打磨成可执行的 spec，而不是替用户做决定。
> 原则：AI 最大的失败模式是"带着错误理解一路执行"。先纠偏，再深挖。

## 访谈四步（按顺序）

1. **先复述理解**。追问之前，用自己的话复述需求核心意图，请人类确认是否理解偏。
2. **顺回答继续挖**。不机械过清单，基于上一轮回答里新暴露的模糊点继续问。
3. **极模糊时发散收敛**。无法判断意图时，列出 2~3 种合理解释（"你可能想要 A / B / C"），让人类选择或补充，不直接驳回。
4. **区分必填与建议**。

### 必填四项（缺一不可，不放行）

| 项 | 说明 |
|---|---|
| 做什么 | 明确的功能行为，可被验证 |
| 为谁做 | 使用者（skill 的终端用户 / 仓库维护者）与典型场景 |
| 关键业务规则 | 输入输出、约束、边界、异常处理 |
| 验收标准 | 做成什么样算对（尽量给出可观察的标准） |

### 建议补充（不强制）

优先级、异常场景、性能预期、风格偏好、与现有功能的关系。

## 本项目高频问题清单

按任务类型选问，不要全部倒给用户。

### 大纲/内容类
- 这是模式 A（用户填空）还是模式 B（AI 共创）的问题，还是两者共用？
- 输入与输出分别是什么格式（Markdown/JSON/界面）？
- 大纲字段有哪些：标题、要点、讲稿备注、配图建议、版式类型？
- 工作汇报与商业品牌 PPT 的大纲差异是否要区分模板？

### 风格/素材类
- 参考模板以什么形式给（链接 / 截图 / pptx）？
- 提取的风格参数包含哪些（主色板、字体气质、版式类型、留白比例、装饰元素类型）？
- 生图用什么模型？是否需要透明底？尺寸（16:9，建议 1920×1080 或 2560×1440）？
- 同一套 PPT 的插画风格如何保持一致（模型、风格提示词、参数）？

### 组装/渲染类
- v1 每页有哪些元素层（背景、装饰、插画、标题、正文、页码）？
- v2 渲染源是 LibreOffice 转 pptx，还是 HTML 精排版（见 product-sop 路线图）？
- 字号自适应的下限是多少（默认 10pt，低于则触发精简/拆页）？

### 改动识别类
- 用户可能在 v1 里改什么：文字、文字位置、插画位置、插画大小、替换插画？
- 识别结果如何回写数据源（`manifest.json`）？
- 是只重渲染改动页，还是受连带影响的页都重渲染？

### 版权/合规类
- 参考模板来源平台的抓取是否做过可行性验证（反爬、条款）？
- 最终产物用途（内部/商用），是否需要在产物中标注字体与素材来源？

## 输出

- 新建 `specs/YYYY-MM-DD-任务名/`（任务名用简短英文连字符）。
- 按 `templates/spec.md` 写完整规格。
- 标题里出现"并且/同时"往往是两个任务，拆开。
- 完成后按固定格式汇报，等待人类确认进入阶段 2。
