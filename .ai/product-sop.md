# Product SOP · 带用户做 PPT 的流水线

> 本文件是 skill 运行时的产品流程（对终端用户）。开发层规范见 `00-workflow.md`。
> 核心原则：内容、风格、素材、组装、渲染五道工序分离，每道工序都可独立确认、可回退；先确定内容和排版，再生成成品。

> 内容必读：[PPT 文案与来源标注约定](knowledge/content-style.md)。其他项目复用本流程时也必须一并读取；后续封装 skill 时须将该文件与本流程一并分发，并在 SKILL.md 中列为必读。
> 视觉与交付必读：[视觉制作与交付约定](knowledge/visual-workflow.md)。[仓库skill入口](../SKILL.md)已引用两份约定；复用时必须连同引用资源保留。此入口不代表已安装或全部规划能力已实现。
> 文献/科研/课堂论文汇报按需读[文献汇报约定](knowledge/literature-report.md)，按受众与时长组织论文、证据和自己的评价。

## 流水线总览

```
① 模式判断与逐页内容（A 填空 / B 共创）
        │  质量门 1：用户确认逐页大纲
        ▼
② 风格参考 → 风格参数（只提取参数，不复用素材）
        │  质量门 2：用户确认风格参数
        ▼
③ 生成素材（背景、插画，AI 生成，风格统一，透明底）
        ▼
④ 组装 v1 可编辑 pptx（文本框 + 独立 PNG + 文本自适应 + manifest）
        │  质量门 3：用户在 WPS/PPT 检查并修改 v1
        ▼
⑤ 渲染前预检 + v2 渲染（逐页整图）
        ▼
⑥ 几何检测 + 视觉自检 → 交付 v1 + v2
        ▼
⑦ 修改闭环：识别 v1 改动 → 只重渲染受影响页
```

## ① 模式判断与逐页内容

开场先判断用户属于哪种模式：

- **模式 A（熟悉主题）**：用户给空白填写表，直接填写每页内容。
  - 提供 `templates/deck-outline.md`，说明每个字段含义。
  - AI 只做字段完整性检查、逻辑顺序建议、字数控制，不替用户生成核心观点。
- **模式 B（不熟悉主题）**：AI 先共创。
  - 先问：主题、受众、场景、时长、希望传达的核心结论。
  - AI 提供 2~3 套内容结构与想法（金字塔结构：结论先行 → 论据 → 支撑数据/案例）。
  - 通过问答逐步收敛，直到填满逐页大纲。
- **两种模式最终汇流为同一份 `deck-outline`**，之后流程完全相同。

大纲要求：

- 一页一个核心观点；每页字段：版式类型、标题、要点、讲稿备注、配图/插画建议、字数约束。
- 总页数包含封面与结尾；在大纲中写明如何收束，课堂汇报的致谢/交流安排按文献约定处理，不到交付时才补漏。
- 每页文字量按版式约束；明显超量时先精简或拆页，而不是依赖缩字号。
- 上屏文案直接表达事实、结论和来源；默认不添加“非审计经营数据”等无实际作用的免责尾句。来源简洁标注，详细口径按需放备注/资料页；会影响结论理解的口径仍在本页说明，具体规则见文案约定。
- 场景默认按场景模板组织：
  - 工作汇报：封面 → 目录/概述 → 背景与目标 → 进展/数据 → 问题与分析 → 下阶段计划 → 总结。
  - 商业/品牌：封面 → 品牌/项目介绍 → 市场/痛点 → 方案/产品 → 优势/数据 → 案例 → 合作/Call to Action → 结尾。

## ② 风格参考与风格参数

- 输入形式：用户给参考模板链接（小红书/抖音等）或上传截图/pptx。
- **合规红线**：只提取风格参数，不复制任何原图、插画、图形、字体。
- 提取参数（写入 `templates/style-params.md`）：
  - 主色板（取主色、辅色、点缀色，给色值）
  - 字体气质（稳重/科技/锐利/圆润 → 映射到白名单字体，不用模板原字体）
  - 版式类型（左文右图、居中标题、三栏、卡片、时间轴等）
  - 留白比例、对齐方式、信息密度
  - 装饰元素类型（线条、几何块、渐变、图标风格）
  - 背景风格、插画风格（写实/扁平/漫画/3D 等）
- 用户可“混搭”：要A的配色+B的版式；只提取参数，需要创作的视觉重新生成。用于说明真实产品的图片另核对来源、使用权和保真要求，不从风格模板里搬图。
- 链接抓取属于 spike（平台反爬/条款未验证）；抓不到时降级为用户上传截图，由 AI 从截图提取参数。
- 质量门 2：风格参数以文字+色板预览方式给用户确认，必要时先生成 1~2 张背景样图。

## ③ 生成素材（背景 + 插画）

- 先按[逐页视觉分配表](templates/style-params.md)规划各页主体与来源，再生成/选图。保持风格统一，按内容改变产品、视角、场景与构图；不把同一商品复制成整套主视觉。
- 同时规划主体在画面中的角色、图文比例与留白；素材数量不作为质量目标。插画过小时，按视觉约定联动重排表格、正文与图片区域。
- 真实产品图、原创概念画面、基于产品图的模型渲染分别处理。用户要求真实图片时先核对实际商品和图源，不以“看起来像实拍”的生成图替代；原图严格保真时使用受保护的独立图片层。具体流程见视觉约定。

- 顺序：先背景，再插画；整套先生成风格样张，确认后批量生成。
- 尽量使用同一工具/已知模型与统一风格提示词，逐张核对一致性；会话工具底层型号未知时如实登记，不声称锁定同一模型。
- 背景：16:9（建议 2560×1440），注意文字安全区（四周留白，避免关键元素落在边缘）。
- 插画：**透明底 PNG**，作为独立元素插入 v1，便于用户在 WPS 中拖动、缩放；命名标注页码与用途。
- 生图提示词模板统一存知识库（`knowledge/`），包含风格关键词、配色（来自 style-params）、构图、负面提示词。
- 生图中的准确文字清单须遵守文案约定：正文和页脚按确认文案输出，不额外添加免责声明、自我解释或制作过程说明。
- 每张素材登记来源与生成参数，便于复现与替换。

## ④ 组装 v1 可编辑 pptx

- 层级：背景图（最底层）→ 装饰元素 → 插画（独立 PNG，可拖动）→ 标题/正文文本框 → 页码。
- 所有中文文本走 `src/text_fit.py`：
  1. 按文本框实际可用区域测量、逐字断行、选最大字号；
  2. 下限 10pt，放不下则反馈精简或拆页；
  3. 设置 normAutofit 兜底。
- 字体只用 `knowledge/fonts.md` 白名单；测量/渲染/PPT 字体名三处一致。
- 同时生成 `output/{任务名}/manifest.json`：
  - 记录每页、每个 shape 的 id、类型、文本、位置/尺寸、关联图片路径。
  - manifest 是⑦改动识别的基准，必须与 v1 同步生成。
- v1 命名：`{主题}_v1_可编辑.pptx`。

## ⑤ 质量门 3：用户检查 v1

- 明确告知用户：v1 是可编辑版，可以在 WPS/PowerPoint 里直接改文字、拖动/缩放插画。
- 用户在 v1 上自由修改；提示其不要删除背景与文本框图层（避免识别失败）。
- 用户确认后进入 v2。

## ⑥ 渲染前预检 + v2 渲染

- 预检：重新打开 v1，核对页数、元素、manifest 一致性；运行文本几何检测。
- **辅助导出与最终重绘分工**：LibreOffice 将真实 v1 导出 PDF/参考 PNG，供内容、字体、几何核对；它本身不会提升设计美观度。用户确认该 v1 后，将参考页、准确文字清单和独立背景/插画交给生图模型整页重绘，协调文字、主题背景与插画。
- 模型可优化排版、配色和质感，但不得改写文案、数字、来源和“近/超”等限定词；不额外添加制作说明或免责声明。详细流程遵守文案约定。
- 用户确认原图后再要求模型美化时，把实际产品图连同参考页送入模型并限制产品形态；交付称为“基于原图的模型渲染”，不能延续原图合成版的“图片像素未变”结论。原图版另行保留，模型图再次核对商品外观及已有切面。
- M1：`prepare-image --v1-confirmed` 只记录已有的人类确认并核对哈希，生成会话交接包；会话实际调用 image_gen，不伪造本地生图 API。输入/v1 改变需重新检查与确认。
- 本次会话工具无法核验底层型号、锁定精确字体或固定像素。v1 严格使用已登记字体，模型 PNG 验收字形气质与可读性；保留原生尺寸，16:9 相对比例误差≤0.5%，不擅自裁切/拉伸/补字。
- M1 实际交付：可编辑 v1、整页模型 PNG、辅助文件及核对记录；`{主题}_v2_展示版.pptx` 整图封装为后续能力。HTML/CSS 可作为今后另行验证的渲染选项，不是本次美化前置条件。

## ⑦ 几何检测 + 视觉自检

- v1 几何检测（真实辅助 PDF）：文字无溢出、越界、非预期碰撞；按背景/插画主体安全区区分合法叠放，仍须查看实际参考图。
- 最终模型 PNG：逐项核对准确文字、数字/单位、限定词和来源，检查遮挡、裁切与风格。M1 为 AI 目视核对，不冒充 OCR 或对位图执行文字框几何证明。
- 视觉自检：逐页对照大纲与风格参数清单（见 `05-review.md`）。
- 自动检测拿不准的交人工确认；字号问题在下限内调整，超量返回内容阶段。最终图生成、AI 初检与人类视觉验收分别记录，不能以文件存在代替验收。
- 给人看的交付先说明成果、正确版本的图片链接及待确认事项；技术字段、日志和哈希放记录或附录。确认仅覆盖本次具体内容，不能把预览、选图或可编辑版认可推断成最终渲染验收。

## ⑧ 修改闭环

- 用户改完 v1 后：
  1. 用 python-pptx 读回 v1，逐 shape 与 `manifest.json` 做 diff；
  2. 定位改动类型（文字、文本框位置、插画位置/大小、换图）与受影响页；
  3. 回写数据源（大纲/风格参数/manifest）；
  4. 只重渲染受影响页（重新准备准确文字及素材交接包；连带影响页一并处理）；
  5. 更新 v2 与 manifest，复检。
- 该能力依赖 python-pptx 读回能力，正式开发前必须先做 `spike/pptx-diff` 验证。
- M1 尚无自动改动闭环；用户修改后先人工同步执行源、重新 build/check 和确认，再做会话重绘。

## 九、场景风格预设（风格参数起点）

- 工作汇报：稳重、克制、高对比；深色标题/浅色底；数据页强调数字对齐；正文大字号保证投影可读。
- 商业/品牌：允许更强品牌色、更大气的留白与装饰；封面/结尾仪式感强；插画与品牌调性统一。

## 十、建设路线图

| 阶段 | 目标 | 关键能力 |
|---|---|---|
| M1 | 单页跑通 | 大纲→独立素材→1 页 v1/文本自适应→辅助导出/检测→用户确认→模型整页重绘/核对 |
| M2 | 完整 v1 | 多页组装、全套素材、字体白名单、manifest |
| M3 | 改动闭环 | pptx diff 识别、受影响页重渲染 |
| M4 | 风格参数 | 截图/链接提取参数、风格预设、生图提示词模板 |
| M5 | 展示渲染完善（规划） | 生图质量/多页一致性与整图封装；其他渲染选项须另行设计验证 |
| M6 | 打磨成 skill/Agent | 入口封装、交互话术、异常降级、模板库 |
