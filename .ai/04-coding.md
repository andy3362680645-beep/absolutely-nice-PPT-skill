# 04 · 编码规范

> 阶段 5 执行规范。三条纪律保证 AI 不超范围、不炫技、不在关键路径上裸奔。

## 三条纪律

### 1. 简单优先

- 用最简单、最直接、最少依赖的方案；能用 python-pptx 基础 API 解决的，不引入复杂抽象。
- 先跑通，再优化；先保证一页 PPT 正确，再批量化。
- 不提前设计未来才用的功能。
- 代码风格统一：小函数、单一职责、函数与参数有 docstring、路径不硬编码（集中配置）。

### 2. 范围纪律：发现但不碰

- 只实现 design.md 列出的步骤和文件。
- 编码中发现的既有 bug、风格问题、可优化项，记录在"发现但不碰"清单，不擅自修改。
- 若必须改范围外文件才能继续，先停下说明原因，等人类确认后再动。
- 不格式化、不重命名、不删除与本任务无关的代码。

### 3. 关键路径先验证

- 排版、渲染、改动识别、外部抓取等关键路径，先写最小验证脚本跑通，再写完整实现。
- 验证脚本放在 `specs/.../` 或任务分支中，可复跑。
- 检查点命令必须实际执行，贴真实输出。

## 中文文本处理（强制）

- 中文文本字号自适应唯一入口：`src/text_fit.py`。
- 禁止对中文调用 python-pptx / power-pptx 的 `fit_text()`（按空格断词，中文失效，见 `knowledge/pitfalls.md`）。
- 三道防线都要落实：
  1. 生成前：`text_fit.best_font_size()` 计算字号与断行。
  2. 打开时：文本框设置 `auto_size = MSO_AUTO_SIZE.TEXT_TO_FIT_SHAPE` 兜底。
  3. 渲染后：PyMuPDF 几何检测，超框则降字号重生成，并进入视觉自检。
- 制作时显式传入[场景配置](knowledge/visual-profiles.json)对应角色下限；10pt仅为历史低层兼容默认值。放不下返回None，调用方先精简、图解或重排，不静默截断或降至技术底线。
- 行距系数用 1.2（纯字形高度会低估，实测结论）。
- 测量字体、渲染字体、PPT 字体名必须是同一套字体（见 `knowledge/fonts.md`）。

## 辅助导出与模型重绘

- LO/PDF/参考 PNG 用于 v1 内容、字体及几何检查；展示 PNG 通过生图模型参考 v1、准确文字与独立素材重绘。不得将普通导出标记为已完成模型美化。
- 用户确认 v1 后才准备生图；输入或 v1 变更使旧确认与交接失效。会话工具调用不伪造为本地 Python API。
- 真实 PPTX、manifest、检测报告、参考图、提示词和最终图用输入/产物哈希关联。文件存在不等于检测通过；生成、AI 内容核对、人类视觉验收分开记录。
- 模型图须核对每项文字、限定词、数字/单位与来源；M1 采用目视核对，不声称自动 OCR 或位图文字框几何检查。模型字形/原生尺寸以已批准口径验收，不擅自补字、裁切或拉伸。

## 代码组织约定

- 代码统一放 `src/`，按模块分文件：
  - `text_fit.py`：中文测量断行（已就位）
  - `outline.py`：大纲读取与校验
  - `style.py`：风格参数、色板提取
  - `images.py`：生图调度与素材管理
  - `builder.py`：v1 pptx 组装
  - `manifest.py`：生成与读取 v1 清单
  - `diff.py`：v1 改动识别
  - `render.py`：真实 v1 的 LibreOffice 辅助 PDF/参考图导出
  - `m1.py`：本地命令与经 v1 确认后的生图交接；会话调用模型
  - `checks.py`：几何检测与视觉自检辅助
- 路径、常量集中配置，不写死盘符和用户名。
- 所有写文件函数幂等（重复运行不产生重复垃圾）。
- 版本化构建保留历史 run；状态更新原子写入，失败不得读取旧导出来冒充成功。文本检索首选 `rg`，避免依赖平台特有检索/编码行为。

## 提交纪律

- 每个检查点通过后提交一次，提交信息按 `git-workflow.md`。
- 提交前确认在 feature 分支；`git status` 检查无大文件、无意外文件。
- 不提交 `.env`、密钥、个人 token。
