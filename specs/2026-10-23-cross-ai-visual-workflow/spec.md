# 需求规格 · 跨 AI 的 PPT 制作流程与视觉质量

> 2026-10-23，需求、可行性与勘察完成，design.md 已获维护者“继续推进”确认；现进入阶段5。下方验收勾选仅在相应证据具备后更新，不提前标记全部完成。

## 一句话需求

让本 skill 在不同 AI 宿主中都能遵循“主题 → 内容检索 → 逐页大纲 → 网上风格检索 → 对应素材生图 → 可编辑稿 → 整页模型协调 → 检查交付”的制作顺序，并提高可编辑版的可读性、图文协调和重点表达。

## 背景与目标

- 用户在豆包工作中使用分发包后，反馈字号小、无效留白多、部分页面堆文字、图表与解释不协调、重点不明显，且评价与致谢混在同页。
- 用户上传的第一张图片为问题总览，其余 11 张为理想视觉方向。它们用于提取设计方法，不直接复用照片、插画或字体。
- 本轮已选择：按场景选择视觉预设；规范、模板、样例、可执行检查一起补充，并输出新分发包。
- 作用环节：内容检索、大纲、风格检索、素材生成、v1 组装、v2 模型渲染与交付检查。
- 当前截图只支持视觉诊断，不能据此声称已经测得豆包原 PPTX 的实际字号或确认其内部生成步骤。

## 四项必填

### 1. 做什么（功能行为）

#### 制作顺序：用户本轮明确补充的核心要求

1. **确定主题**：明确主题、受众、场景、时长、页数和交付范围。
2. **检索相关内容资料**：围绕主题收集可追溯的事实、数据和内容依据；以用户指定资料为主时，区分原文与补充检索。
3. **确定每页具体内容与 PPT 大纲**：写清每页标题、核心结论、上屏内容、依据和讲稿备注，先交用户确认。
4. **网上检索相关主题的 PPT 风格**：围绕主题和场景查找版式与视觉参考，提炼色板、字体气质、标题层级、图文比例及装饰方法，并确认风格。用户提供的参考图一并纳入依据；不得虚构网上检索记录。
5. **用生图大模型制作内容对应的插画与图案元素**：按页规划并生成统一风格的独立素材，以图解辅助解释内容，减少纯文字堆积。背景也纳入统一风格准备。准确流程、图表可承担主要视觉，不机械强制每页增加装饰图。
6. **制作可编辑 v1 并检查确认**：将正文、背景和独立素材排入 PPT，正文、数据与标注保留可编辑对象，插画可独立移动；解决字号、重点与图文排版问题后交用户确认。
7. **用生图模型进行整页协调渲染**：把已确认的正文内容、背景、插画及图案装饰共同交给模型，连同准确文字清单与可编辑稿参考，协调构图、色彩和质感，使各部分和谐美观。
8. **核对并交付**：逐页核对内容、数字、来源、图表含义及视觉效果，提供可编辑版与约定的展示成果。普通 PDF/PNG 导出作为参考与检查工具，最终模型美化必须有实际生图调用。

以上是产品制作流程，仓库开发仍执行独立的六阶段。详细产品规范要同步体现在 skill 入口、产品 SOP、相关模板与知识条目中，确保其他 AI 能发现并执行。

#### 视觉与跨宿主能力

- 增加课堂/文献适用的“课堂图解”预设；商业与工作汇报按各自场景选风格。
- 共用要求：正文可读、图文对应、重点明确、谢谢/交流页独立，且在大纲中计入总页数。
- 内容密集时先精简、图解或调整页数，不依赖无限缩字号；页数受限时回到大纲讨论取舍。
- 概念、过程、比较、数据分别选用适当的示意图、流程、对照与图表。图案应服务内容，不以素材数量替代视觉质量。
- 标题、分组标题、正文、辅助注释区分层次；重点词支持强调色、字重、荧光笔式底纹，并保持文字可编辑。
- 自动检查覆盖可客观验证的结构、字号与几何问题；视觉协调和解释准确性保留逐页审查。
- 其他宿主可使用自身具备的工具制作 PPT；检查能力尽量与特定组装器解耦，不虚构豆包 API 或宿主工具。

### 2. 为谁做（使用者与场景）

- 使用者：本仓库维护者，以及在 Codex、豆包工作或其他具备相关能力的 AI 中使用分发包的人。
- 典型场景：课堂与文献讲解、工作汇报、商业品牌演示。
- 使用频率：每次新建、修改或重新渲染 PPT 时适用。

- 输入：用户主题与约束、用户资料、检索资料、风格参考；本次参考图只作为样式分析依据。
- 输出：更新后的 skill 入口、流程、模板与知识规范，必要检查工具与代表性验证样页，以及独立文件夹与 ZIP 分发快照。
- 本轮仅记录需求；具体影响文件与接口在阶段 3、4 确认后锁定，不提前修改实现。
- 沿用可编辑 v1 与整页模型展示 v2 的区分。v1 自身需要通过视觉验收，后续模型美化不替代 v1 排版改进。
- 生图后的正文、数字、单位、限定词、来源及科学/图表关系必须与确认稿一致。真实产品或证据图片继续执行已有来源与保真规范。
- 风格检索只提取设计参数；无法访问时如实记录并采用可访问参考，不绕过登录或平台限制。
- 缺少网络、生图、PPT 制作或检查能力时说明缺项及影响，不把未执行步骤写为完成；必要替代路径另与用户确认。
- 新发布包与开发源独立，保留旧发布快照；不打包私人资料、参考照片、密钥、字体本体或运行环境。
- 当前已有 M2 和 GM 汇报的未提交工作保持原样；不以本次优化顺带完成、重构或验收它们。
- 本轮不实现自动 PPTX 改动闭环，不宣称已自动适配所有 AI 平台。

### 降级与失败处理

- 风格页面无法访问：保留实际尝试记录，改检索可访问的同主题参考并结合用户已给样张；不把摘要或不可访问链接当作已读详情。必要时请用户提供可访问参考或确认风格参数。
- 宿主缺少生图能力：明确停在素材生成或整页协调之前，保留内容与可编辑稿，说明需要的能力；不得用普通导出冒充模型完成。
- 字体继承、图表文字或页面角色无法可靠解析：定位具体页与对象，列为未验证，结合实际辅助 PDF 和人工审查补核；不以猜测补齐检查结果。
- 局部高亮复杂排版不稳定：优先验证原生文字颜色/字重及独立可编辑底纹形状；仍不可靠时缩小实现范围，在方案中列明限制，不删除本轮重点表达要求。
- 模型重绘导致文字或数据关系错误：只修受影响页，同一问题最多 3 轮；仍失败则保留准确原稿，向用户说明并讨论替代表达。
- 无法实际运行豆包：交付统一复测任务与验收表，兼容性登记为待验证，不把发布包内部检查当作豆包已通过。

## 代码勘察（阶段 3）

### 现状理解

skill 的产品行为由 `SKILL.md` 路由到 `.ai/product-sop.md`、知识与模板。产品 SOP 已区分 v1 可编辑稿与模型整页展示稿，但主题研究和网上风格检索还没有在入口与主流程中完整、显式串联。Python 辅助路径以 JSON 输入、独立图片及字体配置驱动：`outline.py` 校验，`builder.py` 组装并记录 manifest，`text_fit.py` 测量断行，`render.py` 实际导出，`checks.py` 按本次 manifest 核对内容、字体和几何。`m1.py` 是单页已验证入口，`m2.py` 已有多页入口及相关实现，但其正式任务尚未完成验收。上次独立分发由 `output/` 下的一次性脚本产生，并非仓库中可维护的发布命令。

### 发现的具体缺口

| 层面 | 已核对的现状 | 对本轮的影响 |
|---|---|---|
| 制作顺序 | 入口和 SOP 以模式判断、大纲开始；风格阶段偏重接收用户参考 | 须显式加入主题后检索内容、大纲确认后网上检索风格，再分开执行素材生图与整页协调。 |
| 字号标准 | fonts、style-params、review 等仍使用 14/18pt 等旧值；多处把技术下限 10pt 当作可读性下限 | 统一引用场景标准；保留低层兼容默认值，改正注释和指南含义，不靠全局改常量影响旧输入。 |
| 中文适配 | `best_font_size` 从上限向下搜索；`fit_textframe` 写入断行、统一字号和字重 | 可以继续复用；混合字重、高亮处理后的宽度与断行需要单独最小验证。 |
| 强调样式 | builder 支持整框 `fill_color`、对齐与边距，对同框文字统一设色；读回核验也按统一字重和字号比较 | 整框底色不是局部荧光标注；本轮用宿主原生样式及独立样页证明表达，不先扩展 M1/M2 数据模型。 |
| 结束页 | 文献约定允许以结论/讨论收束；大纲未要求致谢单独占页 | 须把谢谢/交流页的独立性写入大纲、正文规范与验收，并计入总页数。 |
| 检查范围 | `checks.py` 依赖本仓库 manifest 的文字对象、有效框及字体；按输入自身 floor_pt 检测 | 无法直接检查任意宿主的 PPTX；需新增面向成品的独立检查入口及角色说明。 |

### 数据与关联点

1. **规范 → 场景配置 → 检查**：字号角色与基准画布需要同一份配置；Markdown 解释与 JSON 不能各维护冲突数值。实际字号必须从成品读取，不能只相信角色说明中的宣称。
2. **大纲 → 素材 → 两版**：每页观点、重点词、图解目的与来源先确认，再生成独立素材；v1 调整后，最终模型参考页与准确文字清单同步更新。
3. **页面/对象角色 → 成品定位**：新角色说明与具体 PPTX 绑定，不根据“谢谢”等关键词或框大小武断认定正文/页脚。缺失、失配、继承样式未知时不能输出完整通过；精确接口在方案确定。
4. **旧 manifest → 新检查**：M1/M2 的输入 schema 和 manifest 保持原样；新检查说明是附加数据，不能冒充自动 diff 或复用旧 accepted 状态。现有检查继续用于原有路径。
5. **中文适配 → 局部强调**：当前写入会重建文字 runs；强调样式的施加顺序、混合字重对宽度的影响与辅助导出需在最小验证中查明。跨宿主使用各自原生对象实现，不能假定统一工具接口。
6. **源文件 → 发布快照**：旧发布器重写多个入口和说明，单改源 SKILL 不保证发布内容相同；新发布过程需核对实际包内规范和新增 JSON 资源。分发测试的私人字体/素材只能进入隔离测试副本。
