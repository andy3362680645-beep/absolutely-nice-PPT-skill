# 需求规格 · 参赛公开技能包发布

> 阶段 1 产出。任务日期：2026-10-25。

## 一句话需求

- 从已经合入最新版公共规则的仓库基线生成一份可直接上传参赛平台的公开技能 ZIP，并明确唯一上传路径。

## 背景与目标

- 为什么做：现有最新候选包生成于本轮文献叙事规则更新之前，不能代表当前最新版 skill。
- 解决什么问题：避免误上传 GM 乳业 PPT 成果包、旧技能包或包含个人偏好与私有资料的开发目录。
- 对应产品流水线环节（大纲/风格/素材/组装/渲染/改动识别/其他）：其他——公共 skill 发布与分发。

## 四项必填

### 1. 做什么（功能行为）

- 使用仓库现有发布机制，从 `origin/main` 已合入的最新公共版本生成新的技能文件夹和 ZIP。
- 对 ZIP 执行结构、清单、完整性、隐私、体积与关键规则版本核对，并向用户提供可点击的绝对文件路径、文件大小和 SHA-256。

### 2. 为谁做（使用者与场景）

- 使用者：仓库维护者 Andy Mao，以及赛事平台读取该技能包的 AI 系统。
- 典型场景：在“中国移动灵犀 AI 助手”参赛页面上传一个压缩包，由平台自动读取技能名称、大小和描述。
- 使用频率：本次参赛提交一次；后续公共 skill 更新后可重复使用相同发布流程生成新版本。

### 3. 关键业务规则

- 输入：已合并 PR #3 的 `origin/main` 公共仓库内容，基线提交 `923f96accf84e2f56717cf2c8a508332f9bd6e69`。
- 输出：一个新的版本化公开技能文件夹及同名 ZIP；压缩包顶层保留单一 `ppt-agent/` 目录。
- 约束：ZIP 小于赛事页面显示的 100 MB 单文件上限；包含 skill 正常使用所需的公共入口、规则、模板、程序与已批准公开样例；不包含 `.local/` 个人风格档案、原始论文、用户 PPT、GM 乳业成果、`output/` 任务产物、字体本体、虚拟环境、Git 元数据或凭据。
- 边界与异常：现有 `ppt-agent-2026-10-25-wireframe-v1.zip` 明确视为旧版，不作为本次上传文件；如现有发布器不能稳定排除私有内容或不能证明包内关键规则等于当前基线，则停止交付并修复发布方案，不手工拼凑后冒称通过。

### 4. 验收标准（可观察、可验证）

- [ ] ZIP 可正常打开，顶层只有一个 `ppt-agent/` 目录，`SKILL.md` 及其引用的公共资源齐全。
- [ ] 包内关键规则与当前 `origin/main` 一致，包含最新文献叙事与页间衔接规则。
- [ ] 发布清单、文件哈希、ZIP 完整性、相对链接和 skill 基础校验全部通过。
- [ ] 隐私扫描通过，包内无 `.local/`、用户身份信息、私有论文/PPT、GM 乳业任务产物或字体文件。
- [ ] ZIP 小于 100 MB；向用户提供准确绝对路径、字节大小、易读大小和 SHA-256。

## 可选补充

- 优先级：高，供当前参赛上传。
- 性能/规模：沿用现有约 11 MB 公共技能包规模，显著低于 100 MB。
- 与现有功能关系：复用 `src.release` 白名单快照与校验能力，不改变 skill 产品行为，不同步个人偏好。

## 待确认问题

- 无。默认以当前已合入 `origin/main` 的最新版公共内容发布，不把尚未合入的开发分支内容带入参赛包。

## 代码勘察（阶段 3 填写）

- 现状理解：`src.release` 已形成完整的非覆盖式发布链路。`build` 先验证一套已通过客观检查、视觉检查及人类确认的四页原创可编辑样例，再按白名单复制公共 `SKILL.md`、`AGENTS.md`、`.ai` Markdown/指定 JSON、`src/*.py` 和依赖说明；随后生成便携说明、示例清单与 `release-manifest.json`，创建单顶层目录 ZIP，并在原子改名之前调用 `verify_release`。验证器逐项检查白名单、相对链接与锚点、PNG、PPTX 结构、字体夹带、私人路径/邮箱/密钥模式、文件哈希、ZIP 路径与内容一致性；`--runtime` 还会在临时解压副本运行四个 CLI 帮助和一次样例 inventory。构建期间源文件、历史任务、旧发布包和 Git 状态变化都会导致失败，不会覆盖既有版本。
