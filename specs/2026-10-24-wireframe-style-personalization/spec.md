# 需求规格 · 线稿优先、视觉选风格与个人偏好

> 阶段1建立，依据维护者连续讨论及2026-10-24更新并同步GitHub的请求。2026-10-25已按确认方案实现；阶段6自审与人类验收状态另见review.md。

## 一句话需求

将默认产品流程改为大纲、真实内容线稿、视觉选风格、正式模型渲染，增加原创文案约束与可携带个人偏好机制，更新可分发skill并通过GitHub分支和PR管理。

## 四项必填

### 1. 做什么

- 主题与受众确认→检索内容资料和真实图片→确认逐页准确大纲→低保真线稿预览与确认→参考图选风格→正式模型渲染→内容、图表、视觉核对与交付。
- 线稿使用真实上屏文字、数据和图像占位/实际素材；检查信息密度、主次、视觉重心、阅读顺序、图文关系、图表标签、来源及独立谢谢页。形态与版式资源在阶段4确定。
- 风格入口两条：AI搜索并展示参考供选择；用户不满意时提供参考图片。AI提取设计参数并组织提示词，不要求用户学习提示词或先用语言描述审美。
- 可编辑PPT改为按需交付，默认以大纲为内容修改源；内容改变后更新线稿及受影响页，保留版本。旧M1/M2命令与历史验收保留兼容。
- 原创编写PPT专用文案规则：去空泛口号、机械对仗、套话和无信息免责句；保留准确限定、学术论证和证据边界。
- 公共规则、个人偏好、本次要求分层；明确记录、读取、修正、删除、暂停、导入导出的操作方式与宿主能力边界。
- 更新发布快照/分发包，并同步GitHub分支、提交和PR；合入由维护者审查决定。

### 2. 为谁做

- 维护者及将skill安装到其他AI平台的使用者。
- 适用于课堂文献、工作和品牌汇报；用户通过看图选择布局与风格，而无需掌握设计术语。

### 3. 关键业务规则

- 输入：主题、受众、时长/页数、资料、参考图片或链接、可选历史偏好。
- 输出：确认的大纲、线稿、风格参数与生成提示词、正式展示页及核对记录；可编辑稿可选。
- 选风格只提取一般设计理念，重新构图并生成原创素材；记录参考来源，不复制模板素材，不保证所有生成结果不侵权。多来源参考不等于自动获得授权。
- 第三方skill复制/修改/再分发须核验许可证及兼容性；署名不代替授权。本轮不引入未指定的外部去AI味skill。
- 精简冗余与学术信息完整并重，不以固定短句数、字数上限或禁用全部否定词代替编辑判断，不承诺通过AI检测。
- 本次明确要求优先于历史偏好；事实与来源准确性不能被偏好覆盖。
- 明确“以后都这样”的长期偏好可记录并告知；单页认可仅作用于本次，多次反馈形成候选偏好后需确认再长期保存。保存适用场景，支持撤回，不记录无关敏感资料。
- 个人档案默认不入公共Git历史或发布包；只分发空白模板及匿名原创示例。宿主不能写入或下次不能读取时，提供可携带文件并说明，不能声称已持久记忆。
- 内容、线稿、风格、最终图分别确认，前一步认可不能替代最终验收。普通导出不能充当模型美化。
- 平台访问受限时换可访问来源或接受用户提供参考，不绕过风控；本轮不新增小红书爬虫。
- GitHub使用分支与PR，不自动合并、不强推、不上传私人文献、参考原图、字体本体和用户偏好。

### 4. 验收标准

- [x] 入口、产品SOP、开发总纲及相关模板对新默认流程表述一致，没有残留的“可编辑稿为必经步骤”。历史功能说明标明适用范围。
- [x] 有可执行的线稿确认清单、内容驱动的布局指导与两条视觉选风格路径，能生成风格提示词而不要求用户编写。
- [x] 文案规则有原创前后示例，覆盖口号、套话、空泛免责及需要保留的学术限定。
- [x] 有个人偏好模板、读取与维护约定；本次要求能覆盖历史习惯，单次认可不会自动变为长期偏好。
- [x] 分发包相对引用完整，包含新增公共资源，排除个人档案；实际执行包检查并记录结果。
- [x] 用至少两个情境核对行为：学术高密度分析、用户更改历史风格偏好；区分规则验证与实际生图验证。
- [x] GitHub分支提交与PR可追溯，记录实际同步结果；不将仅本地完成写成已同步。PR #2已实际创建，等待人类验收合入。

### 验证前置与不做的承诺

- 本阶段不新增平台爬虫、PPT改动识别、渲染引擎或SDK，因此不为这些范围外能力新开spike；搜索按宿主现有能力使用公开可访问资料，不等同于验证了小红书自动抓取。
- 低保真线稿移除v1前置，是新的制作路径。若阶段4方案包含实际样张制作，必须在阶段5先以单页验证准确文字、真实尺寸、密度与图表关系，再扩大样张；不能沿用旧v1路径验收充当新路径实测。
- 若勘察发现必须新增关键路径实现或依赖，回到本评分补充spike与影响，不直接进入正式实现。
- 文档情境复测与真实生图验证分别记录；未实际运行的宿主标为未验证。

### 降级方案

- 风格平台不可访问：换可访问公开来源；仍不满足时接受用户提供参考图，记录实际可见范围。
- 宿主不能生图或无法可靠还原文字/图表：交付已确认大纲、线稿规范与提示词交接资料，说明未完成正式模型渲染，不用普通导出冒充。
- 宿主不能持久读写：提供可携带偏好文件，由用户保存并在后续会话提供；不宣称已自动记忆。
- GitHub网络或认证失败：完成可审查的本地分支提交及发布包，记录失败原因；不得声称远程已更新。

### 关键关联与可复用资产

- release.py的_source_files自动包含.ai下全部Markdown，因此个人实例须放在专用本地目录，公共模板才能放.ai/templates；忽略Git不等于发布程序也排除了文件。设计时须同时约束收集与验证。
- _portable_docs生成使用说明、src说明、字体说明和发行架构；其中存在旧默认流程，须同步更新，避免覆盖源文件时重新引入旧要求。
- build_release当前以已确认四页可编辑样例为打包输入，verify_release检查其结构并隔离运行CLI；可继续用于可选能力示例，不证明新默认流程已实际试跑。
- 现有sample-01与sample-academic-02均存在sample-record.json；能否复用取决于阶段5实际哈希和验收核对，不仅凭文件存在。
- 复用场景字号JSON、原有准确图表与文案核对规范、相对链接/哈希/ZIP/隐私校验和受保护快照机制；不另写中文字号适配器。
- 当前本地分支chore/publish-github，只有本任务spec未跟踪；origin指向维护者指定仓库。阶段5建立独立任务分支前需核对远程基线与既有发布PR状态，避免把未合入旧发布内容重复带入新PR。
