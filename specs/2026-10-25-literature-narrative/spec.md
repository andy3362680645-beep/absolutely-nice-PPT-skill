# 需求规格 · 文献汇报叙事与页间衔接

阶段：6，方案范围内修改、自测与自审完成，已发布PR #3，待人类审查合入。用户已认可拟写规则。本文件不记录个人具体风格、私有论文正文或本地成果路径。

## 一句话需求

将文献汇报“按原文叙事讲清研究、区分方法与结果、明确页间衔接、再作个人评价”的规则落实到公共skill，并通过分支与PR同步GitHub。

## 背景与目标

旧规则强调按时长取舍、不照搬章节，但未清楚要求保留论文自身的论述顺序和解释链，可能产生突兀的自拟提问、重复章节标题或让核查工作占据汇报主线。

影响环节：文献内容组织、逐页大纲、真实内容线稿检查；不调整生图工具或原生PPT代码。

## 四项必填

### 1. 做什么

- 梳理论文大、中、小标题及各节作用，在合理合并拆页时保留论述关系。
- 先介绍原文研究，个人评价、补充材料与延伸建议清楚标明。
- 大纲记录原文章节、本页作用及前后页衔接；跨页章节用有区别且忠实的标题。
- 在展示分数、公式与图表前说明方法、指标含义和适用解释；不把评分结果擅自提升为原因或因果证据。
- 一般核查记录不自动成为展示主线；会影响理解的错误与限制仍需说明，不静默修改数值。
- 修改并检查后推送分支、建立PR，由用户审查合入。

### 2. 为谁做

使用者：本skill的维护者及在不同AI宿主中制作课堂文献、学术与论文案例汇报的使用者。其他工作/品牌场景不强制采用论文结构。

### 3. 关键业务规则

- 输入：真实论文及已明确的听众、时长、汇报重点。
- 输出：忠于论文论述关系的大纲、具有清楚阅读衔接的线稿和可复用指导。
- 保留论文逻辑不等于机械复制全部目录；允许按任务取舍，不固定章节、页数和结构。
- 标题可以通俗改写，不以“非原文词语”一概禁止解释与评价；不得新增无依据的观点、套话或核查口号。
- 原文观点、报告值、制作核查、汇报者评价应分清。重要差异不能因去AI味而掩盖。
- 本次公共变更拟限SKILL.md、.ai/knowledge/literature-report.md、.ai/templates/deck-outline.md、.ai/knowledge/wireframe-layouts.md及本任务留档；具体影响待阶段3确认。
- 个人偏好按现有私有档案机制单独处理，不进入公共文件或分发包；不增加新的记忆服务。

### 4. 验收标准

- [x] 现有“不照搬章节”与新增“保留原文叙事关系”表述一致。
- [x] 入口能发现文献规则，大纲有章节、本页作用及衔接字段，线稿检查包含连续页的理解关系。
- [x] 方法/结果/问题/措施的逻辑不混写，不把所有论文强制套成一种案例结构。
- [x] 评价和核查不会自动挤入原文主线；重要错误处理与原有准确性规则不冲突。
- [x] 相对引用、skill基础校验及实际情境审阅通过；不为纯文档变更伪造PPT检查。
- [x] Git diff无私人偏好、论文正文、产物、机器绝对路径及无关改动；公共更新通过PR #3交付，不自动合并。
